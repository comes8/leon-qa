# Leon QA Web3 测试专区：第三批

第三批把已复核的业务用例接到接口契约、数据准备、串行执行和证据留存。可先用第二批的业务设计生成接口映射，再由人工复核后发布本地或项目 QA 场景。模型只生成候选，不代表接口已执行。

本机入口：<http://127.0.0.1:18170/web3/requirements>。使用原平台账号；启动与诊断沿用 `./leonqa start`、`./leonqa status`、`./leonqa doctor`。

## 页面分工

左侧一级“Web3 测试”包含九个入口：

| 页面 | 用途 |
| --- | --- |
| 需求与建模 | 业务需求与绑定、需求分析/评审、业务建模、现货/合约/资金专项 |
| 测试点设计 | 生成、增量补充、局部修订与评审测试点 |
| 用例与评审 | 选择测试点展开详细业务用例、用例评审、变更影响与回归选择 |
| 接口场景 | 业务用例到登记接口的版本化映射、数据/观察核对、人工发布和历史证据 |
| 测试数据 | 原本地资金工具的数据准备、环境快照与重建 |
| 接口调试 | 原资金工具的单次操作、查询和独立断言 |
| 执行中心 | 已发布业务接口场景、本地 Go 套件或原接口场景的独立执行入口 |
| 报告与证据 | 查看每次请求、响应、断言、变量抽取、失败和受阻步骤 |
| 知识与技能 | 业务Skill、任务Prompt、项目知识文档和资料版本快照 |

前三页上方可切换“业务设计”和“原接口资产”。旧入口继续跳转并保留 project/workflow 参数；业务设计通过 design 参数关联，二者不混用。切换项目清除关联上下文，权限由后端逐次检查。

## 第一次使用：从需求到评审

1. 在“需求与建模 → 业务设计”选择项目，点击“新建业务设计”。填写需求、背景和范围，选择固定资料包版本及本人的 Writer / Reviewer。现货、合约、资金专项方法按需勾选。知识文档可不选；所选文档必须属于当前项目且启用。保存不调用模型。
2. 进入“需求分析”，可补充本次范围；点击“预览并生成本阶段”。预览会列出实际加载的方法文件、原文摘要、上游版本、模型及完整业务输入，不调用模型。点击“确认调用模型”后才提交，消耗所配置模型额度。只提交任务资料和选定方法，不运行文档内的脚本。
3. 生成后核对来源、计算口径、状态、范围和待确认项，点击“复核本版”。部分待确认时明确接受只继续有依据的部分。复核表示允许继续设计，不等于业务方批准、发版批准或测试通过。
4. 完成并复核“业务建模”，再进入“测试点设计”。P05首次生成；P06增量补充保留原ID。条数上限1–12，不要求凑满。测试点有稳定编号、关联规则/模型、前提、触发、预期、核对方法、优先级、设计就绪度、执行准备及来源。
5. 完成“测试点评审”并复核。模型给出修订或阻塞意见时，优先修改对应产物；不采纳需明确填写依据，保留原意见。关键设计就绪度为blocked的产物不能复核。
6. 在“用例与评审 → 详细用例”选择本批展开哪些测试点，确认范围再生成。默认选择设计就绪的测试点，可按需选择待确认项，但对应缺口不能当成确定通过预期。每条用例包含数据、前置、按序动作、逐步预期、独立观察和收尾。
7. 核对用例后复核，再生成“用例评审”。接口、数据、账号或观察源没准备时如实保留执行缺口。完成业务设计不代表已经执行接口。

建议从窄业务需求开始，例如“合成买单5 BASE、限价10、成交2后撤余单；费用0仅限示例；分别核对订单CANCELED、累计成交2、取消3、活动余量0，以及QUOTE可用980/冻结0、spent20/released30”。缺少并发裁决、收敛时限或HTTP错误结构时列待确认，不让模型猜测。

## Skill / Prompt 的实际绑定

| 阶段 | Prompt | 主Skill |
| --- | --- | --- |
| 需求分析 / 需求评审 | P01 / P02 | cex-requirement-review |
| 业务建模 | P03 / P04 | cex-business-modeling |
| 现货 / 合约 / 资金专项 | P10 / P11 / P12 | cex-spot-matching / cex-futures-risk / cex-funds-reconciliation |
| 测试点生成 / 增量补充 | P05 / P06 | cex-testpoint-design |
| 测试点评审 | P07 | cex-testpoint-review |
| 用例 / 用例评审 | P08 / P09 | cex-testcase-design-review |
| 变更影响 / 回归选择 | P13 / P14 | cex-change-regression |

主链路为“需求分析 → 业务建模 → 测试点 → 测试点评审 → 用例 → 用例评审”。每步必须完成最新有效上游的人工复核。需求评审和三个专项可选；若已生成，则相关下游会依赖它们。不会一次强制调用全部9个Skill：每次只加载主Skill、选中的专项方法、它们的完整参考文档和本次Prompt。任务Prompt变量映射为本次输入字段，原文件快照不改。

## 修改、失败与追溯

- “编辑条目”提供普通表单，修改测试点或用例后另存完整新版本，保留ID和未编辑条目。旧复核不覆盖，新版重新复核。
- 选择测试点/用例后点击“局部修订所选”，模型仅输出所选ID；服务器把未选条目原样合并。不能借局部修订新增、改名或移除其他条目。
- 更新需求、绑定或相关上游产物后，下游旧版本显示待更新。旧产物和复核记录保留，但不能作为当前有效依据。
- 历史下拉框只读查看旧版；展开条目可点击来源，读取该输入版本的完整原文。每版保存资料摘要、方法文件摘要、Prompt、模型元数据、输入版本和上游产物ID。
- “变更与回归”可用当前已复核需求分析对比历史已复核用例及其对应评审；旧基线沿原依赖ID取资料，不用当前同名规则替代。历史来源以BASE-v前缀区分，不继承旧测试通过结论。
- 生成失败时查看“阶段调用记录 → 查看记录”。结构已解析而业务校验失败的候选会保存，可“以候选稿人工修订”；修订不覆盖失败记录。首次人工录入可展开字段规范，所有内容仍要过编号/来源校验。
- 同一个请求号重复提交复用原任务。网络结果不确定时按“原请求确认或提交”，不要换新请求号反复调用。每个任务同一时间只生成一个阶段；服务重启后中断任务不会自动重放，先核对记录。
- 模型结构校验失败最多进行一次结构修复请求，可能再次消耗额度；完整业务阶段不会自动重跑。业务校验失败不自动重试。失败或中断不代表供应商未计费。
- “导出设计记录”导出输入快照、全部产物、复核和追溯信息。模型密钥不进入设计快照或导出文件。

输入历史最多50版；超过后创建关联新任务并保留原记录。界面列出最近100条个人任务、最近200条产物索引和30次调用；已知任务可用URL直接打开，完整历史以导出为准。

## 资料版本与知识库

来源目录：`/path/to/leon-qa/resources/web3-cex-business-skills/`。首份不可变快照包括9个Skill、14份Prompt、25份参考Markdown、9份agent展示元数据及1份README，共58文件。原目录不移动、不修改，评估记录和可执行脚本不作为业务规则导入。

“知识与技能 → 检查源目录更新”只扫描已登记目录。确认后导入新快照，旧版保留。任务固定使用所选资料版本，不会因源目录变化静默替换。知识文档保存到任务输入快照；后续原文修改也不会改写旧输入。

现有项目知识仍区分本地模拟、币安外部参考和项目材料。方法文件是设计方法，币安资料是外部参考；任何一种都不能自动当作公司的已确认规则。源目录无法访问只影响同步，不影响已存快照的阅读与设计。

## 第三批：业务用例到接口执行

1. 先在“用例与评审”完成最新业务用例和用例评审，再到“接口场景 → 业务设计适配”。选择固定的业务设计、用例、接口服务、环境和执行范围。当前本地验收使用独立的 `Leon QA · 现货本地契约 v2` 与 `Leon QA · 本地现货隔离环境 v2`，不会改写原有 v1 接口资产。
2. 新建适配批次后先点“预览并生成接口映射”。预览不调用模型，页面显示业务版本、接口文档摘要、环境变量名和方法约束。确认后才提交生成任务；请求号用于幂等重试，网络结果不确定时保留原请求号。
3. 生成的候选必须逐例检查：`coverage_ids` 精确对应原测试点、每个原业务步骤都有 `business_steps` 映射、先创建会话再引用变量、每个步骤有整数 HTTP 状态断言和业务字段断言、金额使用独立十进制预期。接口缺口或观察能力不足时保留阻塞，不能把缺口改成“通过”。
4. “另存接口修订”创建新版本，原模型稿、失败候选和证据只读保留。修订不会改变原业务用例 ID、覆盖范围或接口服务；新版需要重新做技术检查和人工复核。
5. 发布对话框只允许发布无数据/映射阻塞的场景。发布只创建固定版本的原生接口套件，不发送业务请求；页面明确显示“发布不表示执行通过”。
6. 在“执行中心”确认本次环境和隔离范围后运行。每条用例拥有独立变量上下文，按 setup → action → observe → cleanup 串行执行；写请求不自动重试，失败用例的依赖步骤标记为受阻，其他独立用例继续。任务完成与业务通过分开判定。
7. 在“报告与证据”展开当次任务查看原始请求、响应、断言、变量抽取和错误。导出包含固定业务版本、接口目录快照、发布版本、所有任务（包括旧于最近50条的任务）和当次证据。

本批真实本地验收使用三条已复核现货用例：下单后 NEW/冻结、成交2后的 PARTIALLY_FILLED/支出、撤余单后的 CANCELED/数量口径。每条均新建 session，按独立公式核对 5×10、1000−50、2×10、50−20，取证后清理。本地模拟为同进程合成契约，不能证明生产撮合、独立账务、异步收敛或真实交易所行为；其余业务测试点仍需另建接口契约和授权环境。

### 失败、停止和版本变化

- 任务状态 `succeeded` 只表示执行器完成；`receipt.failed_cases` 非零时页面显示存在失败用例，不显示为通过。
- 某一步失败后，同一用例后续依赖步骤写入 `blocked`；已开始的其他用例继续。停止请求在请求边界生效，已发出的请求保留证据，未开始的用例和步骤明确记录为未执行。
- 服务重启只把排队/运行任务标为 `interrupted`，不自动重放写请求；原候选和部分证据保留。
- 业务设计、接口目录或环境摘要改变后，旧适配版本不能继续生成、发布或执行；旧执行证据仍可导出。原生接口中心入口也继承版本、权限和环境门禁。
- `local_mock` 只允许登记的 `127.0.0.1:18171/api/v1/Ntesterc_web3/mock/` 路径；`project_qa` 必须配置 `qa`/`testnet` 和允许域名，禁止币安生产域名；`reference_only` 只做设计。

## 能力边界与后续批次

第二批完成业务设计和评审追溯，第三批完成上述接口适配与本地合成执行闭环。后续仍需为真实 CEX 现货/合约、资金、链上资产和 DEX 分别登记经授权的 QA/testnet 契约、独立账务/链上观察源、异步收敛和清理方案，再逐模块验收；不能直接把本地契约切到生产域名。

原v1接口流程及本地Go工具继续按原能力使用；Go套件仍限本地TESTUSD内部划转。导入现货、合约、链上资金方法不等于具备真实撮合、合约、DEX执行支持。本批模型候选使用既有配置但接口路由验收使用隔离假模型；实际网页运行只访问本机合成接口，没有真实交易、外部业务接口或公网部署。

运维见 [README_QA_OPERATIONS.md](README_QA_OPERATIONS.md)，旧Web3流程见 [README_WEB3.md](README_WEB3.md)。第三批备份、验收和回退说明位于 `.runtime/web3-area-batch3-*`，只保存在本机。
