# Leon QA 本地套件运行：第三阶段

“运行诊断”可只读检查本机依赖及执行器。统一启停和异常恢复见 [运维手册](README_QA_OPERATIONS.md)。

第四阶段已增加“本地数据准备”入口，支持独立手工环境、隔离数据集、快照、原始初值重建及清理。操作步骤与生命周期见 [本地数据准备](README_QA_LAB.md)，阶段边界见 [已确认计划](LEON_QA_PHASES.md)。

本阶段把第二阶段的任务 API 和独立执行器接入现有 Leon QA 网页。沿用原登录、项目成员权限和视觉风格；后端、Go 业务判据、数据库表和已验收执行协议没有修改。

## 从哪里进入

网页地址：`http://127.0.0.1:18170`。

1. 使用原来的平台账号登录。
2. 左侧打开“接口自动化 → Web3 测试工作台”。
3. 点击工作台右上角的“本地套件运行”。
4. 选择自己已加入的项目。当前套件是“同用户资金账户与现货账户内部划转”。

页面路由为 `/api-automation/runner`。选中任务后，URL 保存项目与任务编号；浏览器刷新仍读取同一任务，而不是全局 latest 报告。别人取得 URL 也必须登录并通过原有权限校验，页面不是公开报告分享链接。

## 一次正常工作流程

1. 选择“常规回归”，执行超时默认 300 秒，可设置为 1–900 秒整数。
2. 点击“运行常规回归”。页面提交任务后返回独立运行号，不需要保持终端前台打开。
3. 在右侧查看生命周期：排队中 → 执行中 → 已结束。任务结束不代表业务通过，还要看单独的测试结论和资源清理状态。
4. 打开“业务用例与断言”。当前常规回归有 14 个必跑业务用例，点击任一用例读取本次运行的真实证据。
5. 核对规则、业务对象、预期、实际、单位和后端断言结果。金额保留协议中的原始最小单位字符串，网页不重算业务通过规则。
6. 展开测试数据前后快照、接口请求与响应、服务日志，结合执行日志和状态事件排查。
7. 在“证据文件与来源”下载 summary.json、junit.xml、runner.log、用例 bundle 等报告清单内文件；文件请求使用现有登录认证。
8. 需要复测时点击“复用运行配置”，再点击运行。每次复测创建新请求标识与新运行号，原任务和证据继续保留。

左侧历史仅显示当前用户在当前项目中的最近 100 条任务，可以按运行号筛选。选择不同项目或任务会清空旧详情，迟到响应不会把旧项目的数据覆盖回来。

## 两种运行类型

| 类型 | 目的 | 怎样判断 |
|---|---|---|
| 常规回归 | 验证资金划转业务与测试工具本身 | 看回归结论、14 个必跑用例及清理状态 |
| 故障自检 | 故意少记一最小单位，证明断言能检出错误 | 自检 PASS、原始门禁 FAIL 为预期；不能计作业务回归通过 |

自检页面会突出显示“已检出预期缺陷”，默认筛选失败断言。至少需要余额、资金守恒、对账三类精确证据；一次缺陷可能同时触发其他流水断言，不应硬写成固定三条失败。

四类已完成测试结论仍由后端提供：PASS、FAIL、ENV_ERROR、NO_TESTS。取消、超时、中断没有有效测试结论，网页不会把它们显示为回归通过。

## 异常时怎么处理

- **提交响应超时**：页面先保存当前用户与项目下的请求标识；自动刷新历史确认是否已创建任务。需要重试时使用同一参数与同一请求标识，不生成第二条任务。不要在不确定原请求结果时改参数连续提交。
- **执行器离线**：页面显示离线及启动说明。允许提交排队；离线期间也可以取消排队任务，取消不会启动测试进程。
- **取消执行中任务**：点击“取消任务”并确认。先显示取消处理中，等待后端结束本次进程组和清理资源，最终才显示已取消。
- **超时**：后端标为已超时，保留日志和事件，不显示有效通过结论。
- **执行器异常阻塞**：页面显示后端错误，暂停新提交。先按第二阶段运维文档排查归属和 cleanup.json，不通过修改网页状态来跳过问题。
- **连接失败**：保留已展示内容并标记信息可能过期，轮询降低频率；连接恢复后点击刷新。
- **权限失效**：后端继续拒绝读取/取消/下载，页面清空缓存的任务详情与证据，沿用平台登录处理。

日志按后端字节偏移继续读取，切换日志流会重新从该流起点读取。为避免大日志拖慢页面，界面最多保留最近 300,000 个字符；完整日志从证据文件下载。离开页面会结束本页面轮询，不会停止后台任务。

## 与原 Web3 需求工作台的关系

原工作台的需求分析、用例评审与接口用例发布流程继续保留。新页面运行的是已登记的 Go 套件；目前没有把任意 AI 草稿直接转换成该固定套件。新业务需要先补相应套件或适配器、明确业务口径和验收，再登记到执行器。

本阶段仍使用本机合成资金划转环境，不连接真实交易所，不接收交易所密钥，也没有部署到公网。现货撮合、合约风险和 DEX 的真实测试环境适配不属于本轮页面交付范围。

## 开发与验收

主要文件：

- `frontend/src/views/testing/qa-runner/index.vue`：页面与用户交互。
- `frontend/src/views/testing/qa-runner/controller.ts`：请求状态、幂等重试、异步响应隔离和增量日志。
- `frontend/src/api/v1/testing/qaRunner.ts`：复用平台认证请求层的 API 客户端。
- `frontend/tests/qa-runner.test.ts`：状态边界单元测试。
- `frontend/tests/qa-runner-ui-scenarios.json`：8 组浏览器验收场景定义。

复查核心 TypeScript 与前端构建：

```bash
cd /path/to/leon-qa/frontend
node_modules/.bin/tsc --noEmit --target es2022 --module esnext \
  --moduleResolution node --strict --skipLibCheck \
  src/views/testing/qa-runner/types.ts src/views/testing/qa-runner/model.ts \
  src/views/testing/qa-runner/controller.ts

node_modules/.bin/esbuild tests/qa-runner.test.ts --bundle --platform=node \
  --format=esm --outfile=../.runtime/qa-runner-ui-unit.mjs
node --test ../.runtime/qa-runner-ui-unit.mjs
npm run build
```

这里使用项目已有 TypeScript 4.9 的 node 解析模式检查独立核心代码，不改动整个项目原有编译配置；Vue 页面另经过真实生产构建和浏览器验证。没有安装新依赖，也不需要另装 Postman、JMeter 或浏览器测试插件才能运行这个固定套件。

验收索引：`.runtime/phase3-acceptance-path.txt`。保存浏览器结果、截图、下载字节核对、后端交叉记录、构建日志及测试输出。基线索引：`.runtime/phase3-baseline-path.txt`；交付和选择性回退索引：`.runtime/phase3-delivery-path.txt`。

执行器的配置、启动、停止、资源归属和第二阶段 API 说明继续参见 `README_QA_RUNNER.md`。
