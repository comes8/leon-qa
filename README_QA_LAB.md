# Leon QA 本地数据准备：第四阶段

第五阶段已在本页下方增加“资金接口调试”，可执行划转、按原号查询、查看业务记录与流水、SDK断言及调试证据导出，见 [第五阶段操作说明](README_QA_DEBUG.md)。以下保留第四阶段的数据准备与生命周期说明；“第四阶段不提供划转”的描述仅指该阶段原始范围。

本页管理可反复准备的**本机合成资金状态**。它复用 `leon-qa-kit` 的 Go CLI 和 SDK；手工环境与自动回归任务各有独立服务、数据库、进程身份和文件目录。

## 网页入口与一次操作

网页：`http://127.0.0.1:18170/api-automation/data-prep?project=1`。使用原平台账号登录，选择自己加入的项目。

- 从“接口自动化 → Web3 测试工作台”右上角点击“本地数据准备”。
- 也可从“本地套件运行”页右上角进入。

1. 点击“启动手工环境”。等待操作记录显示“已完成”、环境变为“运行中”。
2. 创建 A：资金初值 `1000`，现货初值 `0`。
3. 创建 B：资金初值 `20`，现货初值 `5`。
4. 点击数据集名称。每组有独立 Go 数据集 ID，包含 alice、bob 两个合成用户，各有资金/现货账户；输入的是**每位用户**的初值，共四个账户。币种固定 TESTUSD。
5. “刷新快照”会通过本环境的 Go SDK 读取实际账户状态。“页面刷新”则重新读取平台已保存的环境、数据集和操作记录。
6. “清理所选数据集”只清理选中组的实际业务数据，保留最后快照和操作历史，不影响另一组。
7. “按初值重建”以该组最初保存的金额创建新 Go 数据集 ID。旧 ID、旧快照和原因留在历代记录；不能通过重建偷偷改种子金额。需要不同金额时新建另一组。
8. 不使用时点击“停止所选环境”。它销毁该环境的独立数据库，释放本机容量；保留平台快照及记录。已停止环境不能直接复用或重建其数据，需要启动新环境并重新创建。

关闭网页不会停止环境。手工环境会持续占用本机资源，直到主动停止、执行器正常退出或异常恢复时回收。此阶段不提供自动闲置回收。

## 金额与限制

- 使用十进制文本，范围 `0`–`10000000`，最多八位小数。不接受负数、科学计数法或隐式四舍五入。
- 后端与网页传递最小单位字符串，网页用 BigInt 格式化，避免 JavaScript 浮点误差。
- 同一用户同一项目最多一个活动手工环境，本机最多两个；每个环境同一时刻只接受一个变更操作。
- 环境列表显示自己在当前项目的最近 40 套，操作显示最近 100 条；没有自动删除历史，但此页面尚无更早历史的分页查询。
- 自动回归始终新建自己的临时环境，不会使用此页的数据；停止手工环境不取消自动回归。
- 数据准备区管理初始状态，不把账户快照显示成业务测试通过结论。第五阶段的同页调试区另行执行划转、查询和显式业务断言。

## 请求、权限与恢复

新增接口前缀：`/api/v1/Ntesterc_qa_runner/lab`。

| 接口 | 内容 |
|---|---|
| `GET /state?project_id=...` | 当前用户、当前项目的环境、数据集、操作和限额 |
| `POST /operations` | 固定动作 start / stop / create / inspect / rebuild / delete |
| `GET /operations/{id}` | 本人操作的最终回执 |

所有接口沿用原 JWT 登录和项目成员校验；同项目不同用户也不能读取或操作对方环境。HTTP 不接受命令、项目路径、环境变量、远端地址或任意动作。平台不向浏览器下发 Go 管理密钥、服务令牌、内部监听地址或凭据文件。

写操作先持久化，再由独立执行器领取。响应丢失时，页面保存同一用户/项目的请求标识，先核对原操作；按原请求重试不会重复创建。相同标识更换参数会被拒绝。数据集版本变化时需刷新后再操作。

执行器重启会核对并回收它所属的手工进程与容器，标记中断、保留快照，**不自动重放变更或恢复业务数据**。即使在写入 PID 前崩溃，也会通过固定监督进程模块、随机令牌及三重容器标签发现资源。原 PID 被复用时不会据此终止无关进程。清理失败时保留容量占用并报告错误，先排查执行器日志，不能直接删除归属记录。

平台数据库新增 `qa_lab_environments`、`qa_lab_datasets`、`qa_lab_operations` 三表，只保存管理状态、种子、快照和审计信息。余额真值仍在独立合成数据库。进程创建时间使用 DOUBLE，保留进程身份核验所需精度。

本地私有运行目录为 `.runtime/qa-runner/manual/env_<id>/`：每环境独立二进制、启动描述、凭据、数据指针、操作日志。目录和凭据按私有权限创建；不应提交 Git 或复制到公开报告。

## 启动与排错

沿用第二阶段的登记及独立执行器，无额外服务、依赖或浏览器插件：

```bash
cd /path/to/leon-qa/backend
.venv/bin/python scripts/qa_runner.py init
.venv/bin/python scripts/qa_runner.py start
.venv/bin/python scripts/qa_runner.py status
```

`init` 现在确保原三张任务表及新增三张数据准备表存在，不重建已有业务表。如果开发原型中的新环境表曾用 FLOAT，还会仅将该表的 `process_created` 改为 DOUBLE。

- 启动失败：查看 `.runtime/qa-runner/worker.log` 及该环境私有日志，核对本机 Go/Docker 和登记路径。
- 操作失败：先看操作结果和资源状态；失败不等于完成。未知变更结果会保守关闭所属环境，保留已保存快照。
- 执行器离线/异常：页面暂停新数据变更。恢复后刷新，以服务端状态和原操作回执为准。
- 快照标为不可用：仅作历史证据，不能继续发业务请求。新启动环境有新身份。

停止执行器：`.venv/bin/python scripts/qa_runner.py stop`。这会关闭其手工环境，操作前先保存需要查看的快照；不会清除平台历史。

## 开发与验收

后端 `Ntesterc_qa_runner/lab_*.py` 负责固定动作、串行领取、路径/资源归属与快照持久化；前端 `qa-lab` 负责交互与请求状态，不重新计算业务判据。

本阶段以两组隔离数据、显式原始种子重建、单组清理、并行自动回归、强制中断恢复和网页操作验收。测试、截图、初次失败及修复后复测均由 `.runtime/phase4-acceptance-path.txt` 定位。选择性回退由 `.runtime/phase4-delivery-path.txt` 定位。工具包源码本阶段不变。

原套件网页见 [第三阶段说明](README_QA_RUNNER_UI.md)，执行器运维见 [第二阶段说明](README_QA_RUNNER.md)，后续边界见 [阶段计划](LEON_QA_PHASES.md)。
