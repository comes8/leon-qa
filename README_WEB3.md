## 1. 先运行已有的完整示例

1. 登录后进入「接口自动化 → Web3 测试工作台」。选择「Web3 QA 个人版 · 本地样例」。
2. 打开「Web3 全流程验收 · 四业务与资金冲突」。这是实际调用已配置 DeepSeek 模型生成、修订并评审的任务。
3. 在「需求分析」检查新增行为、回归范围、测试数据、待确认事项和覆盖矩阵；在「规则来源」查看当时引用的规则内容和摘要校验值。
4. 在「用例与评审」展开场景，查看接口编号、前序取值、请求覆盖和断言。场景中的步骤串行关联，各场景独立准备数据。
5. 在「执行报告」确认本机模拟环境，点「重新执行」。不需要 Postman，也不需要在 JMeter 安装插件。
6. 展开报告，对照每个字段的判断方式、期望和实际值，查看请求与响应。历史下拉框保留不同执行编号，包括失败记录。
7. 「导出本次记录」导出整个任务的规则快照、分析、草稿、评审、发布映射与执行历史；发布的场景也存在原有「接口用例」和「接口报告」中。

启动现有本地安装：

```bash
bash /path/to/leon-qa/.runtime/start.sh
```

## 2. 输入一条自己的需求

在「新建测试」选择接口服务、测试环境、知识库、Writer 和 Reviewer，输入本次改动，而不是只写“测试现货全流程”。例如：

> 在本机多业务模拟中，现货下单 quantity=5、price=10，显式成交 2 后撤销余单。核对同一订单的累计成交为 2、剩余冻结为 0；独立流水 spent=20、released=30、free=980、locked=0。补充已撤订单重复撤单、未知订单和 0.01 步长错误的场景。每条用例使用独立会话，金额按 Decimal 比较。

工作顺序：

1. **分析需求**：提取本次行为、关联回归、正向/反向/边界/异常/业务链路覆盖和缺失条件。
2. **复核范围**：点击「评审与修正分析」。对照真实规则确认或修正预期，保留确实未知的问题，并填写复核依据。依赖未知规则的用例不会直接发布。
3. **生成用例**：点击「确认范围并生成用例」，平台调用 Writer，然后调用 Reviewer，并执行确定性技术检查。
4. **处理意见**：可点击「按评审意见修订」，或编辑草稿后重新评审。模型意见也要复核，不是每条模型建议都正确。修改前的分析和草稿最多保留最近 5 份快照。
5. **发布所选场景**：选择本批可执行用例、记录评审备注，发布到原生接口用例集。
6. **执行并看证据**：确认目标环境后执行。关联步骤失败会阻塞后续依赖步骤，其他独立场景继续。网络失败不会被当成预期的 HTTP 500；HTTP 400/404/409 等可以依据明确断言判为通过。

生成和评审会调用所选模型并消耗其额度；重跑已发布的接口用例集不重新调用模型。每批先控制在一个变更或 3–8 个场景，避免一次生成过长导致截断。

## 3. 公司项目如何接入

### 接口与环境

- 在原有「接口中心」建立项目和接口服务，通过已有 OpenAPI/Swagger、Postman 或 cURL 导入能力录入真实接口。先确认单接口请求能够正常执行。
- URL 建议使用 `{{base_url}}`，令牌使用环境变量引用；不要将密钥贴进需求、知识库或提示词。
- 新工作台选择「项目测试环境」，并在环境变量中配置：

```text
qa_environment = qa
qa_allowed_hosts = qa-api.example.internal
base_url = https://qa-api.example.internal
```

`qa_environment` 也可为 `testnet`；多个允许域名用英文逗号分隔。只允许匹配本次环境的 HTTP(S) 地址。默认不向币安已列出的主站交易域名执行工作流。`本机模拟`模式仅允许本机地址，`币安参考设计`模式只设计用例，不执行交易请求。

### 鉴权

普通 Token、API Key 沿用接口中心已有功能。新增 `Binance HMAC（测试环境）` 选项：

- API Key 填 `{{api_key}}`，Secret 填 `{{api_secret}}`，在测试环境保存其值。
- 当前 HMAC SHA256 适配器对 **Query 中的参数**签名，添加 `timestamp`、`recvWindow` 和 `signature`，设置 `X-MBX-APIKEY`。业务参数不要拆到 JSON 或表单请求体；签名不含 RSA/Ed25519、钱包签名或自动校时。
- 已用固定测试密钥核验签名计算，但尚未用用户的币安测试网账户联调。真实接入时应先检查接口鉴权、时钟和产品规则。

### 业务知识

新增了 3 个知识库、7 份规则文档和 3 份提示词：

| 资料 | 用途 |
| --- | --- |
| 币安现货参考规则 | 下单/查询/撤单、过滤器、签名与未知执行状态、订单事件 |
| 币安 USDⓈ-M 合约参考规则 | 持仓模式、下单、只减仓及参数适用范围 |
| Web3 多业务模拟规则 | 与本地模拟代码对应的会话、现货、合约、资金与 DEX 行为 |
| Web3 · 需求分析 v1 | 提取需求、方向、风险、覆盖矩阵和待确认事项 |
| Web3 · 接口用例生成 v1 | 生成有来源、有数据依赖、有业务断言的结构化草稿 |
| Web3 · 接口用例评审 v1 | 检查来源、规则适用性、覆盖、断言与证据闭环 |

公司规则单独建库，不要直接把币安预期套到公司接口。每份规则至少写：产品/模块、适用环境、版本、规则编号、状态迁移、金额口径、错误结构、接口字段、幂等范围、观察点和待确认事项。缺少撮合、账务或链上查询接口时，应列明依赖，不能仅凭下单成功推断资金正确。

模板位于 `backend/app/api/v1/Ntesterc_module/Ntesterc_web3/templates/`。模板需要填写和业务确认后再入库。当前资料检索支持中文需求和字段检索，不强制安装向量数据库；既有向量检索配置仍可使用。

## 4. 自己的 Prompt 和 Skill 如何复用

- 业务规则、测试经验、状态机和金额校验方法，可以整理成 Markdown 文档上传项目知识库。
- 分析、生成、评审的方法可以融入三份平台提示词，但要保留结构约束及来源要求，否则生成结果可能无法成为可执行场景。
- Codex 的 Skill 文件不会仅因上传而在网页内执行。网页把文档当作知识；执行接口的是平台受控步骤。不要把任意 shell/Python 指令当作模型可执行步骤。
- 新业务应补充本公司的真实字段和规则，再让 AI 生成场景。一次通过的场景可发布为回归套件，后续版本重复执行；修改已发布接口或步骤后，工作台要求重新评审，避免审批内容与执行内容不一致。

## 5. 当前验证边界

已验证的完整本机链路：现货下单→部分成交→撤余单→查单→独立流水；合约只减仓→查仓；资金划转→同量幂等重试→余额/笔数；DEX 报价→模拟兑换→模拟回执；同幂等标识改量冲突。

这些模拟接口没有真实撮合、手续费或真实链上结算。当前没有完成真实私有账务数据库、WebSocket 订阅、EVM 签名广播、区块确认和回滚、真实充提、资金费/强平联调，也没有做多用户部署与容量验收。接口中心已有能力与新工作流相连，不等于这些业务已全部覆盖。

本机地址会直接连接，避免被电脑代理错误转发；远程项目接口仍沿用既有网络配置。模型连接错误、规则不足、接口目录不匹配或服务重启中断会保留错误，不会生成虚假的成功报告。
