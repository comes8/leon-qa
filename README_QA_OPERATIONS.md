# Leon QA 本地资金测试工作台：使用与运维

适用范围：本机 Leon QA 网页、平台后端、独立执行器，以及同用户资金账户↔现货账户内部划转的合成 TESTUSD 环境。现货撮合、合约、链上和 DEX 的真实公司接口不在这个版本的验收范围。

## 每天从哪里开始

在终端进入平台根目录：

```bash
cd /path/to/leon-qa
./leonqa start
./leonqa doctor
```

网页入口 `http://127.0.0.1:18170`。使用原平台账号登录，从“接口自动化 → Web3 测试工作台”进入“本地套件运行”或“本地数据准备”。两个页面都有“运行诊断”按钮，显示本机依赖、执行器和本人当前项目手工环境的检查结果。诊断只读，不执行启停，也不表示业务测试通过。

本机既有安装应保留 Python虚拟环境、Node、Go、Docker Desktop、前端依赖及工具包登记。启动命令不安装/升级依赖、不创建替代数据库。Docker未启动时，先启动Docker Desktop再重试。

## 统一命令

| 命令 | 行为 |
|---|---|
| `./leonqa start` | 检查并启动既有本机依赖，启动/核对后端、前端和独立执行器；重复执行复用已验证进程 |
| `./leonqa status` | 输出只读状态；即使服务离线也便于查看，不创建表、不启动测试 |
| `./leonqa doctor` | 检查数据库、Redis、已登记Docker、工具包、执行器及前后端；不就绪时退出码2 |
| `./leonqa restart backend` | 只重启平台HTTP服务；独立执行器与手工环境继续运行 |
| `./leonqa restart frontend` | 只重启网页开发服务器，可能需要浏览器刷新 |
| `./leonqa restart worker` | 停止并重新启动执行器；会中断正在运行的回归、关闭手工环境；历史保留 |
| `./leonqa restart` | 整体应用重启，影响同上一条；原数据不会自动重建 |
| `./leonqa stop` | 先停止执行器，再停止前后端。平台MySQL、Redis、数据库卷、历史和日志保留 |

也可用 `start/stop backend|frontend|worker` 只处理指定组件。启停由本机文件锁串行管理，不在网页接收Shell命令。启动时若检测到非所属端口占用，命令报错并保留对方进程；不会按端口直接kill。首次兼容旧PID指针时核对实际可执行文件、参数、工作目录和监听归属，随后保存精确进程创建时间。

后台日志使用追加方式，避免重启覆盖原日志。`status`退出码0代表状态读取完成，不代表全部就绪；以`doctor`和其`overall`字段判断服务就绪。

## 两种工作方式

**整套自动回归**：打开“本地套件运行”，选择常规回归并执行，等待测试结论和资源清理。核对14个必跑业务用例、预期/实际、HTTP记录、独立SQL快照及证据文件。故障自检故意少记一个最小单位，原始门禁FAIL而自检PASS是预期；不能当作常规业务回归通过。

**逐步业务调试**：打开“本地数据准备”，启动手工环境、创建1000/0数据集，在“资金接口调试”中发起100划转、按原号查询，填写900/100预期执行业务断言。重复同号同载荷不重复扣款；把预期写为901应显示具体FAIL，改回900复测保留两次记录。详见[第五阶段操作说明](README_QA_DEBUG.md)。

关闭网页不会停止后台任务或手工环境。手工环境同用户同项目限1套、本机最多2套；不使用时在页内停止环境。自动回归为每次运行准备自己的临时环境，与手工数据分离。

## 健康检查与恢复语义

- 网页显示检查时间；诊断不能取得新结果时清除旧绿色结果，提示检查连接、登录或项目权限。切换项目、关闭窗口后的迟到响应不会覆盖当前显示。
- 执行器同时核对心跳和本机进程身份。启动时完成原任务/手工环境恢复后才显示空闲，不把“已启动进程”当成“恢复完成”。
- 执行器在没有手工变更正在执行的轮询阶段，约每2秒检查手工服务的loopback `/healthz`；每次最多1.5秒。该接口检查合成数据库连接。
- 单次失败不会立即销毁环境；连续3次失败会回收该环境所属进程和容器，数据集标为不可用，保留最后快照。探测及清理耗时会影响实际间隔；没有长期业务操作时通常数秒至十余秒完成发现和回收。
- 手工操作执行期间由原命令超时、错误和回执处理；周期探测可能延后。当前无自动闲置超时回收。
- 执行器正常停止或异常重启会回收旧手工环境，不自动重建，不自动重放划转。未知划转结果保留原请求号；环境仍在时先查询；环境已关闭则只能查历史，不能把新环境下同号请求当作原请求查询。
- 进程和容器均按所属身份处理；PID缺失时通过固定监督进程模块、运行号和随机令牌发现进程，容器核对三重标签。验证失败时保留错误，不清空记录冒充清理完成。

## 常见问题怎么处理

| 现象 | 检查与处理 |
|---|---|
| 网页打不开 | 在根目录执行`status`和`doctor`；检查前端18170、后端18171。已有其他进程占用时先确认用途，不要直接kill端口 |
| 执行器离线 | 常规任务可以排队；确认原任务记录后`start worker`。手工数据页等待执行器就绪才允许新操作 |
| 执行器异常阻塞 | 先检查worker.log、该运行cleanup.json和Docker；处理依赖后`restart worker`核对回收，不删除归属或改数据库状态跳过 |
| Docker不可用 | 启动已登记的本机Docker；不回退到其他Docker上下文或远端。恢复后再启动/重启执行器 |
| 报告导入失败或缺失 | ENV_ERROR没有有效通过结论。看日志/状态事件、核对summary和用例证据。找回文件不会自动把历史错误改为PASS，应另起新运行复测 |
| 取消或超时 | 等待最终状态及清理结果；不是测试PASS。原日志保留 |
| 账户快照显示环境已关闭 | 这是历史观察值。启动新环境并创建新数据，不能继续操作旧数据库 |
| 划转UNKNOWN | 先按原业务号查询，勿换号自动重试；明确当前数据集和用户作用域 |
| 清理失败 | 保留失败状态/容量，恢复Docker后重启执行器重新核对。不要Docker prune，不删除整库、整个.runtime或审计表 |

平台固定依赖是本机`ntester-local-mysql`（127.0.0.1:13389，已有`ntester-local-mysql-data`卷）和`ntester-local-redis`（127.0.0.1:16389）。统一命令只启动镜像、loopback端口和数据库卷符合既有安装的容器，不创建空库替换缺失数据，也不停止这些依赖。迁移安装或改端口时需要先评审并更新本机配置。

## 文件、证据和隐私边界

| 内容 | 位置 |
|---|---|
| 前端/后端追加日志 | `.runtime/frontend.log`、`.runtime/backend.log` |
| 所属进程记录 | `.runtime/frontend-process.json`、`.runtime/backend-process.json` |
| 执行器配置/日志/锁 | `.runtime/qa-runner/` |
| 自动回归证据 | `.runtime/qa-runner/runs/job_<id>/report/` |
| 手工环境私有目录 | `.runtime/qa-runner/manual/env_<id>/` |
| 本阶段验收和回退索引 | `.runtime/phase6-acceptance-path.txt`、`.runtime/phase6-delivery-path.txt` |

每次运行/调试分别保存身份、源码摘要、前后快照和原始失败。用户只能通过已登录项目权限读取自己的任务、环境和操作。需求/用例编号、评审备注作为文本关联标签，不代表自动同步外部需求系统。

手工目录含服务令牌、管理密钥和独立SQL观察连接，**不能提交Git或公开分享**；源码交付快照排除`.runtime`和配置。浏览器只收到白名单诊断信息和合成业务证据，既不接收这些凭据，也不能指定任意URL、SQL或命令。分享自行填写的备注或导出JSON前先审阅内容。

本阶段仅将自有执行器两表的`process_created`从FLOAT迁移为DOUBLE，用于以后精确核对进程身份。旧历史中已丢失的小数无法恢复；恢复仍需验证实际进程与标签，不据舍入时间猜测归属。平台其他业务表不重建。

## 验收与后续

本阶段验收范围包括统一启停/重复启动、依赖诊断、后端独立重启、空闲环境HTTP失联回收、排队/取消/超时、报告缺失、所属清理失败阻塞与恢复、强制终止执行器后的归属发现，以及网页诊断和资金调试回归。具体完成项以验收记录为准；详细结果和初次失败/复测保留在本阶段验收目录。

Docker不可用通过登记一个不存在的本机Unix socket进行隔离验证，不停止全机Docker；清理失败通过专用执行器包装器对专用归属容器注入；测试不会修改真实交易所或公开部署。稳定性结论限已列本机场景，不是长时间生产负载或高可用认证。

第七阶段才选择真实公司测试接口，补齐鉴权、数据工厂、只读对账、网络范围和清理授权后做联合验收。现货撮合、合约、链上和DEX按业务分别新增套件。

阶段边界见[计划](LEON_QA_PHASES.md)，已有操作详见[套件运行](README_QA_RUNNER_UI.md)、[数据准备](README_QA_LAB.md)、[资金调试](README_QA_DEBUG.md)。
